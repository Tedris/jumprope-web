## Input Affordance Contract — One Button

Everything is one virtual button: **Space** (window keydown/keyup) or **pointer press/release**
(canvas pointerdown/pointerup). There is no other input surface.

| State | Press | Release | Status |
|-------|-------|---------|--------|
| idle | starts the run (`startRun()`) | ignored | ✅ implemented |
| running | arms hold timer (`performance.now()` at press) | jumps; hold duration → jump height (variable-height) | ✅ implemented |
| choose | held as intent | applies `offer[0]` (placeholder for pick-two, Phase 3) | ✅ implemented |
| over | held as intent | saves best score, restarts via `startRun()` | ✅ implemented |

Invariants later phases must honor:
- `e.repeat` is filtered (no autorepeat re-trigger); `preventDefault()` on Space (no page scroll).
- Input sets **intent flags consumed at simulation step boundaries** — wall-clock time is touched
  only to measure physical press duration, so jump timing never depends on frame load.
- Deferred: ~0.1 s input-buffer forgiveness → Phase 4 (FEEL-01); blur/`pointercancel` hardening → Phase 5.

## Accessibility Contract

- `#hud` carries `aria-hidden="true"` — **deliberate Phase-1 decision, not oversight.** Rationale:
  the HUD text is rewritten every animation frame (`textContent` writes in the rAF loop), which
  would spam screen-reader live regions with unsolicited announcements; and the game's core
  judgment (rope arrival timing) is inherently visual-temporal and not conveyed by these strings.
- No focusable/tabbable elements exist; the whole surface responds to Space globally.
- Scope honesty: this is a minimum-viable a11y stance, not a WCAG pass. Real coverage —
  `prefers-reduced-motion` damping of wobble/shake, pause/hidden-tab handling, resize legibility —
  is Phase 5's contract (UI-01…UI-03). **Phase 5 must revisit this `aria-hidden` decision rather
  than inherit it silently.**

## PS1 Visual Direction — Mood & References

**Mood:** warm-paper diorama. A cream-beige daytime stage (`#f7f3e8` air, `#d8d0bd` dust) with one
scarlet figure in it — sun-bleached PS1-era cartridge palette, not a dark neon retro take. Chunky
flat-colored blocks, zero specular ambition, visible pixels when scaled. The feel target remains
*Scarlet Skips* (Yerk Games, 2026) in spirit — one-button rhythm-roguelike joy — demaked, never cloned.

| Technique | Status | Owner phase |
|-----------|--------|-------------|
| Low internal resolution (480×640 buffer) + nearest-neighbor upscale | ✅ implemented | 1 |
| Flat/unlit shading | ✅ implemented (MeshBasicMaterial form) | 1 (refined by 2) |
| Fixed camera, no procedural camera motion | ✅ implemented | 1 (readability contract by 2) |
| Ordered dithering | ⏭ deferred — no shader dither pass exists yet | 2 (PRES-01) |
| Vertex-snap wobble on world geometry | ⏭ deferred | 2 (PRES-01) |
| Original low-poly skipping character | ⏭ deferred (placeholder rose box only) | 2 (PRES-02) |
| Blob-shadow depth cue; rope readable through full arc | ⏭ deferred | 2 (PRES-03) |
| Reduced-motion damping of wobble/shake | ⏭ deferred | 5 (UI-02) |

Interpolation note (must-hold invariant): all visual motion interpolates the canonical `rope.phase`
via wrap-aware `lerpPhase(prev, curr, alpha)` — dither/wobble/audio in later phases derive their
timelines from `rope.phase` too, never from their own clocks (SKELETON §Breaks-if-wrong).
