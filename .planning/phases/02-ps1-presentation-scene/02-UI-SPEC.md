# Phase 02 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase has no DOM chrome UI.** The "UI" is the rendered WebGL scene itself: camera
> framing, palette, canvas sizing, in-frame readability cues, and the one-button input
> affordance. The only DOM surface is the existing `#hud` overlay (unchanged structure).
> The PS1 pipeline is the design system — every knob below is either signed-off fact or a
> Wave-3 binding requirement.

### Pipeline contract (signed off — do not re-litigate)

| Knob | Canonical value |
|------|-----------------|
| Internal resolution | `INTERNAL_H = 240` rows; width = `round(240 × canvas.w / canvas.h)`, clamped `Math.max(2, …)`; NearestFilter, mipmaps off, pixelRatio locked to 1 |
| Vertex snap | block S = 2 internal px, NDC snap after `#include <project_vertex>`, w preserved; **world materials only**; `customProgramCacheKey = 'ps1-snap'` |
| Dither/quantize | single fullscreen pass: sRGB-encode FIRST, then standard 4×4 Bayer + 31-level (~15-bit) floor quantize, indexed at `floor(vUv * uInternalRes)` |
| Fog | color-matched to sky, near 7 / far 22 |
| Light | one white `DirectionalLight`, intensity 2.4 at (−4, 7, 3); **no ambient fill** (D-05 literal) |
| Shading | flat-shaded vertex-lit Lambert facets (D-05) |

## Typography

HUD only; the scene contains no rendered text this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body/Label (score lines, prompt) | 16px | 400 | normal (single centered lines) |
| Display (score number, `#hud-score`) | 32px | 400 | normal |

Two sizes, one weight — do not add more. Prompt text wraps centered; no truncation machinery.

**Legibility requirement:** HUD text sits over the dark sky `#2a3440` since plan 02-02. Current
`color: #222` (`css/style.css:18`) measures ≈ 1.2:1 against it — effectively invisible.
**Contract value: `#hud { color: #f4f0d8 }`** (the already-approved pale, so no new hue enters
the palette). If the team insists on the Phase-5 deferral noted in 02-02-SUMMARY, the checker
should treat this as a documented, visible defect rather than a silent pass — it is a one-line
change and the score is a core readout.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (~60%) | `#2a3440` | Sky, fog, canvas/page backdrop (60% of the frame is sky/fog surface) |
| Secondary (~30%) | `#3a4a42` + `#1d2630` | Floor quad; horizon silhouette slabs and handle boxes (dark props) |
| Accent (~10%) | `#c94f6d` | Reserved for: character torso + head cap, scarf segments. Nothing else — not the rope, not the stage |
| High-contrast read | `#f4f0d8` | Reserved for: the rope tube (unlit, fog-exempt) and HUD text color. Nothing else |
| Destructive | none | No destructive actions exist this phase; failure feedback is behavioral (rope settles + shake), not a color |

Accent reserved for: rose jumper identity (continuity with the 2D prototype, D-13) and its scarf.
Pale is reserved for rope/HUD legibility (D-09) — it must never be spent on decoration, or the
rope loses its contrast budget.

Rule from the sign-off checklist that stays binding: rose and pale must **read clearly through
the dither with correct brightness** — "no dark linear-RT frame" (sRGB-encode-before-quantize).

## Rendered Scene Contract (Wave 3 requirements)

Binding for plan 02-03 — this is what the ui.safety-gate checks the finished frame against.

### Camera (D-16)
- Fixed side-on-with-slight-angle; target framing `(2.6, 2.2, 8.6)` looking at `(0, 1, 0)`
  (current shipped interim frame is the spike's `(0, 1.5, 6.5)` → `(0, 1.2, 0)` — Wave 3 refines
  it; either way, **zero camera motion in `render()`**, ever).
- The whole rope arc (over head → under feet) stays fully in frame at all window aspects.

### Character (D-13/D-14/D-15)
- Chibi rig from primitives, built once at scene-build time: head ≈ 0.55 cube on a ≈ 0.9 body,
  two dark dot-block eyes, limb groups. Rose `#c94f6d` family on torso/head; neutral limbs.
- All pose quantities derive from `theta = lerpPhase(prevPhase, rope.phase, alpha) × 2π`
  (`theta = π` ⇔ tube low point at feet, matching `atFeet` window 0.45–0.55) plus
  `player.y`/`squash`. No mixer, no clips, no local accumulators.
- Scarf: 3-box chain, segment *k* lags by `k × 0.4` rad off the same clock.

### Rope (D-08/D-09/D-10/D-12)
- Real rotating arc: sag-baked `CatmullRomCurve3` (radius ≈ 1.0, pivot at handle height ≈ 1.05)
  through `TubeGeometry(…, radius 0.05)`, unlit `MeshBasicMaterial({ color: '#f4f0d8', fog: false })`
  — bright through the whole arc, snap-exempt, no glow pass.
- Two small dark handle boxes at the pivot rim, turning with the arc.
- Trip (`status === 'over'`): pivot freezes at the feet-at-rest angle with a decaying shake
  `sin(Δ×42) × exp(−Δ/200)` on `view.now` deltas — short, then stillness. No particles/hitstop (Phase 4).

### Depth cue (D-17)
- Blob shadow: flat `CircleGeometry` r ≈ 0.55, black at 0.45 opacity, snap-exempt (stable
  reference under crawling geometry), `scale = opacity/0.45 = 1 / (1 + playerY × 0.01 × 0.8)`.
  Continuous through the jump; returns on landing.

### Stage (D-18)
- Floor stays one 40×12 1×1-quad (calm via vertex sparsity). 4–6 dark silhouette slabs at
  x ±14, z behind the floor, fully inside the fog falloff; nothing tall within 6 world units of x = 0.

### Canvas & input behavior
- Canvas buffer tracks the window (`windowSize()` coerce → 480×640 fallback), CSS
  `100vw/100vh` + `image-rendering: pixelated`; canvas background = sky hex `#2a3440` so the
  pre-first-frame page never flashes a foreign color. Live resize handled by render3d's passive poll.
- Input affordance: one button — pointer down/up anywhere on the canvas, or Space. Hold length
  = jump height. Idle/over: any press/release starts a run; no menus, no buttons, no cursor states.
- Idle screen is alive (D-15): rig bob `sin(now/400) × 0.05` + slow pivot twirl `now/1400` —
  visually distinct from gameplay sweep speed; never frozen.

## UAT Amendment (2026-10-17) — user sign-off on deployed build

Live browser UAT rejected the first build (scene near-black; rope read as a
spinning circle). Root causes fixed in `js/render3d.js`; user then approved
the look on the GitHub Pages deployment. Amended contract values:

| Item | Old (spike) | New (signed off) | Why |
|------|-------------|------------------|-----|
| Final-pass `toSRGB` | `pow((c+0.055)/1.055, 2.4)` | `1.055*pow(c,1/2.4)-0.055` | spike formula was the sRGB DECODE — crushed every pixel; the spike had never been seen by the user |
| Rope sweep axis | `rotation.z = -theta` (screen-plane circle) | `rotation.x = +theta` (hands-axis forward sweep) | in-plane spin has a static silhouette ("circle going around") |
| Rope geometry | full circle r=1.0, pivot y=1.05 | hand-to-hand arc, reach 0.75, pivot y=0.7, handles ±0.5, arms out to grips | D-08/D-10 reinterpreted for axis sweep: rope must read as rope in two hands |
| Light / fog / fov / limbs | 2.4 / 7-22 / 40 / floor-green limbs | unchanged — misdiagnosis round reverted | |

All four UAT checks (look parity, rope-feet beat coincidence, readability,
personality + HUD legibility) passed on commit `bbf09f0`.
