## Challenges & growth areas

1. **A2 enumerates behavioral censuses well and source-shape censuses badly — the epic's one genuine process miss, in three families.** (a) *Import-specifier censuses:* 8.1's recommended `js/skins.js` landing died at `tests/summitapproach.test.js:831-832`, which pins `js/shell.js` at EXACTLY four `'./'` specifiers — a family the pre-scan never named, saved only because D3 carried a written alternative. (b) *Harness stub shapes:* 8.1's red iteration #1 (13 reds) came from frozen bare-`Color` stubs with no `.set` method, not from any shipped-behavior fence. (c) *Prose and VCS state as census surface:* 8.2 went red because a comment literally wrote `location.search` inside a token-census window (the review's fix made token censuses comment-stripped), and the porcelain diff arm reddened both §6 twins twice — `mods/` at 8.3, `tests/fixtures/` at 8.4 — because `git status --porcelain` collapses untracked new directories. All four are mechanical and enumerable. → action A2.
2. **The census-forced shell-internal landing is now doctrine, and it has a balance sheet.** Five for five Epic 8 factories landed inside `js/shell.js` (8.1 forced, 8.2/8.3 deliberately — "the 8.1 D3 scar holds"). The upside is real: zero import-graph surface, so nothing new for a census to catch and the boundary fence never wobbled. The cost: `js/shell.js` is now the repo's largest file (1,036 lines), it is un-importable under Node, and every Epic 8 suite tests it by **cross-source extraction** (`new Function` over the extracted function text) plus pairing fences — the most indirect test path in the repo, born entirely of census pressure. The same file is the one Epic 7's ledger :291 named as the blocker for parallel development. → action A3 (debt row `w3`, park reaffirmed).
3. **Record accuracy consumed 11 of 23 patches.** Doc-drift, miscounts, and stale line cites in all five stories: 8.4's create round miscounted its own pre-scan (16 → 17), 8.5's D8 spelled "692 + 8 = 700" against 9 enumerated legs, and a donor cite drifted `:187-189` → `:191-193` because 8.1 added a comment. The law that emerged is right — frozen donors keep their stale lines, drift is documented in the new record and never "fixed" in a frozen file — but a fifth of review capacity going to prose says the create round's cites need verification against HEAD at create time. Observation, no new rule: the reviews caught every one, so the cost stayed inside the loop.
4. **One P2 product defect reached review that the design never considered: an untimed await.** 8.3's single boot-path `await loadModManifest(...)` had no deadline — a stalled-but-accepted connection would hang the boot forever, and the NFR3 load budget has no way to report a hang. Fixed with `AbortSignal.timeout(3000)` plus a mutation-probed deadline leg. The generalizable rule: **any await on the boot path needs a deadline**; `!url` short-circuiting keeps the default boot request-free, which is what made the hole invisible to every default-boot leg.
5. **The hardware half of "proven" is still unpaid, and it is now the only unpaid thing.** v2 is live and the sandbox lanes are green floors, not verdicts — SwiftShader software raster cannot speak for NFR1 on a 2020-era integrated GPU. L1/L2 are `:263`'s hardware legs (the item that slipped three epics, this time with a written checklist) and L3 is Player Fuel's GPU re-confirm. Nobody is blocked on code; the loop has no way to make a person look at a screen. → action A1, and it is the critical path.
