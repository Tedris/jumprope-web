## Story

As a mod maker,
I want to describe changes in a JSON manifest the game reads,
So that the disguise's depth can grow without anyone touching the engine.

8.3 is Epic 8's mod surface and its engine is **a validator**: decision P1 is ANSWERED (see AC1) and the manifest surface is one static JSON file, fetched shell-side at boot under the 8.2 URL mechanism (`?mods=<path>` rides the same `location.search` read — the SAME parsed `equipSearch` string, so the frozen location census stays satisfied by construction). A manifest is applied as pure DATA: one `fetch`, one `JSON.parse`, one strict validator, and — when valid — its `skin` record composed into Story 8.2's equip expression at the ONE consumption site, flowing through `normalizeSkin` into 8.1's application seam. Nothing a manifest carries is ever evaluated, imported, or executed (the data-only law, FR36); every violation — parse error, unknown key, wrong type, out-of-range color, oversized payload, path violation, non-OK response — drops the WHOLE manifest to shipped defaults with total silence (UX-DR2, NFR16). The sim graph, `js/game.js`, `js/rope.js`, `js/render3d.js`, `index.html`, `css/` are byte-zero this story; the product diff is `js/shell.js` (three shell-internal factories + two module-scope lines + the boot-site composition extension) plus the committed example asset `mods/mint.json` (the epic's dogfood: the mint skin as a manifest, the schema's live witness).

### Decided notes (pinned design decisions — AUTHORIZED by this file; dev implements, does not re-litigate)

1. **D1 — the validator: `parseModManifest(text)`, shell-internal, all-or-nothing.** Pure (text in → validated manifest object or `null`); the ONE `JSON.parse(` site in js/shell.js, inside `try { } catch { return null; }`. Laws, in order: parsed value must be a non-null non-array object; `Object.keys` ⊆ `{v, name, skin}` (a `__proto__` key from JSON.parse is an OWN key — the unknown-key gate rejects it, and `Object.prototype` stays clean); `raw.v === 1` (strict — `'1'`/`2`/absent die); `typeof raw.name === 'string' && raw.name.length >= 1 && raw.name.length <= 64`; if `'skin' in raw`: record is non-null non-array object, keys ⊆ `{name, colors}`, `name` same string law, `colors` non-null non-array object with keys ⊆ `{rose, prop, limb}` and ALL THREE present, each `Number.isInteger(v) && v >= 0 && v <= 0xffffff` — this is the BH-4 range gate (missing color key → `Number.isInteger(undefined)` false → drop; no half-record is representable). ZERO IO tokens (the §a purity list plus `Math.random`). Returns the parsed object (already-validated DATA; consumers read `?.skin`). Never throws, never logs.

2. **D2 — the fallback law is mechanical: every `null` is the same silence.** `loadModManifest` and `parseModManifest` return `null` on every failure mode (AC3's list, AC2's guards); the boot site composes `modManifest?.skin`, so `null` contributes `undefined` → `normalizeSkin(undefined)` → the placeholder record → zero color writes — the byte-inert 8.1/8.2 composition (every default boot stays bit-identical BY CONSTRUCTION, and with no param present the loader never even reaches `fetch`).

3. **D3 — the loader factories: three functions, shell-internal, zero new files/imports.** (The 8.1 D3 scar holds: a fifth static specifier reddens summitapproach §4.2 :831-832 — everything lands beside `SKINS`/`resolveSkinParam` in js/shell.js module scope.)
   - `function resolveModsParam(search)` — the `mods` twin of `resolveSkinParam` (D3 there): `const v = new URLSearchParams(search).get('mods'); if (typeof v !== 'string') return null;` then the PATH LAW (all must hold, else `null`): `v === v.toLowerCase()`; `v.length <= 128`; `v.startsWith('mods/')`; no `:`/`\`/`?`/`#`/`%` chars (scheme, drive, query-fragment, and double-encoding gates); `v.endsWith('.json')`; `v.split('/')` has no empty segment (kills `//`, `mods//x.json`) and no `..` segment (kills traversal). Returns `v` VERBATIM or `null` — the value is a PATH under `mods/`, never a URL; zero IO tokens.
   - `async function loadModManifest(url)` — shape pinned: `if (!url || typeof fetch !== 'function') return null;` (**short-circuit order is the AC2 law: no param ⇒ `fetch` is never TOUCHED**) then `try { const res = await fetch(url); if (!res.ok) return null; const bytes = new Uint8Array(await res.arrayBuffer()); if (bytes.byteLength > MOD_MANIFEST_MAX_BYTES) return null; return parseModManifest(new TextDecoder().decode(bytes)); } catch { return null; }` — ONE `fetch(` call site in js/ (the shell; `js/audio.js`'s `fetchFn` is its own injected channel, untouched), ONE fetch per boot, NEVER rejects (the catch makes the boot-fork error spies stay silent), never logs.
