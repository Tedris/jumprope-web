<domain>
## Phase Boundary

The core-value loop feels joyful and sounds alive: a press slightly early or late (~0.1 s) around the timing moment is forgiven instead of tripping — via an input-buffer timer on the phase clock, with the sim staying pure (FEEL-01); skips, near-misses, and trips produce juice (hitstop, shake, particles) scaled by significance, with near-misses registered as a distinct event with callout and streak feedback (FEEL-02, FEEL-03); the player hears distinct SFX for jump, skip, near-miss, trip, and card-pick over a looping vibe track that the rope never locks to (AUD-01, AUD-02); audio "just works" from the first press on Chrome, Firefox, and iOS Safari with no silent broken state (AUD-03); and the player can mute and set volume, persisted across sessions (AUD-04). No pause/tab-hidden handling, reduced-motion, or resize hardening — those are Phase 5. No meta progression, no beat-lock (out of scope).

<decisions>
## Implementation Decisions

### Feel — sim-side forgiveness and events (FEEL-01, FEEL-03)
- **D-N01:** The input buffer lives in the simulation core, not the shell: `run` gains a `buffer` field (seconds remaining), `tickRun` decays it by `dt` on the phase clock and consumes it at the feet-crossing to resolve a would-be trip as a forgiven pass. Press delivery is a new **optional trailing parameter** `press = null` on `tickRun` (same DI shape as `rng = Math.random`), defaulting to today's exact behavior. The window is one exported constant (`BUFFER_SEC ≈ 0.1`) in `js/game.js` (per FEEL-01; per D-01 in Phase 1 — the buffer must live inside the `three`-free import graph; per pattern in `js/game.js` `tickRun(..., rng = Math.random)`). Verifiable: pure Node tests step `tickRun` with presses offset ±0.05/0.1/0.15 s from feet-cross and assert trip vs skip. — **Reversibility:** reversible — the field and parameter are additive with a null default; deleting both restores the current behavior exactly, and no saved data encodes `buffer`.
- **D-N02:** `tickRun`'s return record gains an `events: [...]` array (`'jump' | 'skip' | 'nearMiss' | 'trip' | 'offer'`) alongside the existing `tripped` flag, which stays for backward compatibility. `tickRun`'s current return is destructured positionally by name in `js/shell.js` and frozen tests; an added key breaks neither (per pattern in `js/game.js` `tickRun` return `{ run, rope, player, tripped }`). All consumers of juice/audio/callouts read events only from this channel — never from timing side-channels. — **Reversibility:** reversible — additive return field; consumers can be reverted to the `tripped`-only read in one commit.
- **D-N03:** Near-miss is a machine-checkable sim predicate: a feet-crossing pass is a **near-miss** if it was resolved via the D-N01 buffer (forgiven late/early press) or cleared with clearance below a derived margin (`NEAR_MARGIN`, a fraction of the existing `minHeight = 18 / windowMul` threshold in `tickRun`). A near-miss still counts as a skip and additionally emits `'nearMiss'`; `run` gains a `streak` field incremented on near-miss, reset on a clean skip or trip (per FEEL-03). Verifiable: pure tests assert event/streak sequences over scripted passes. — **Reversibility:** reversible — `streak` is in-run state only (nothing persists across runs), and the predicate is a constant away from being disabled.
- **D-N04:** Callout/streak feedback renders through the **existing HUD prompt channel** — the `flashUntil`/`flashName` flash pattern in `js/shell.js` `tickPick`/`updateHud` already proves this mechanism for card names; near-miss callouts ("CLOSE! ×3") reuse it, no new DOM surface or render3d text (per pattern in `js/shell.js` `flashName`/`updateHud`; CARD-02's at-a-glance identity stays DOM-side). — **Reversibility:** reversible — swap to an in-scene callout later without touching sim or event plumbing.

### Juice — shell/render-side, never sim-side (FEEL-02)
- **D-N05:** Hitstop is a shell accumulator gate: on a juice event the `frame()` loop pauses `tickRun` stepping for a tier-scaled ms by delaying the `while (acc >= STEP)` drain — `STEP`, `dt`, and every sim function stay byte-identical, and hitstop never mutates sim state (per ARCH-01; per pattern in `js/shell.js` `frame()` accumulator with its existing 0.25 s clamp). Verifiable: Node shell tests with a stubbed clock can count sim steps during a hitstop window. — **Reversibility:** reversible — removing the gate restores the plain drain; nothing in run state records hitstop.
- **D-N06:** Juice presentation is render-side and tier-driven: a data table maps event tier (skip < nearMiss < trip) → { hitstop ms, shake amplitude, particle burst }. Shake is a **post-pass UV jitter in the existing Bayer/post shader, not camera motion** — the camera keeps its Phase-2 "zero camera motion, ever" invariant so the timing reference never moves (per pattern in `js/render3d.js` camera block "Never touched again in render() — zero camera motion, ever"; matches the Out-of-Scope line "Free-look camera / heavy shake during judgment"). Particles are pooled flat low-poly quads in `js/render3d.js` — no post-processing beyond the existing single dither pass (per PROJECT.md constraint "no post-processing beyond simple dithering"). The WebGL layer reads state/events read-only and never feeds back (per D-01 in Phase 1). — **Reversibility:** reversible — all juice knobs are data in the tier table and shader uniforms; deleting them returns the scene to the Phase-2 render path.

### Audio — one new module, zero new dependencies (AUD-01..04)
- **D-N07:** All WebAudio lives in a new `js/audio.js`, imported **only** by `js/shell.js`, so it sits outside the sim import graph by construction — the same containment the Phase-1 split used for `three` (per D-01/D-03 in Phase 1; `tests/boundary.test.js` stays green because no test-graph module imports it). SFX for jump/skip/near-miss/trip/card-pick are **procedurally synthesized** (short oscillator + noise-buffer voices, AUD-01) — zero binary assets and the zero-npm-dependency rule intact, static-file delivery unchanged (per PROJECT.md constraint "static files only"). Verifiable: shell tests with a stubbed audio API assert one voice-per-event mapping. — **Reversibility:** reversible — the module exposes an event-in/void-out interface; sample playback can replace synthesis behind the same calls later.
- **D-N08:** AudioContext lifecycle: created lazily on the **first user gesture** (the shell's existing `press()` path is the only gesture), `resume()` called on every subsequent gesture and on `visibilitychange`/`focus`; a suspended context after any input is treated as a bug with a visible diagnostic state, never a silent one (per AUD-03). The context is never constructed at module load or page load. Verifiable: Node tests with a stubbed AudioContext assert create-on-first-press and resume-on-gesture, never auto-play. — **Reversibility:** reversible — lifecycle is one small state machine in `js/audio.js`.
- **D-N09:** The music is **one pre-rendered looping audio file** played via `AudioBufferSourceNode { loop: true }` through a single `GainNode` master volume bus shared with SFX — no procedural music engine, no beat-lock: the audio layer only **reads** sim events, never writes to rope/player/run, and the rope phase remains the canonical clock (per PROJECT.md Key Decision "SFX + music without beat-lock"; per AUD-02 and the Out-of-Scope line "Procedural music engine"). Verifiable: a boundary-style grep/audit confirms no import path from `js/audio.js` into sim mutation functions and sim holds no audio references. — **Reversibility:** reversible — the track is one file behind one `playTrack()` call; swapping it is content-level.
- **D-N10 (user-adopted 2026-10-22 00:45):** Audio-settings persistence: one new localStorage key `jumprope-audio` storing `{ muted, volume }`, implemented through the existing injectable-storage pattern of `loadBest`/`saveBest` in `js/game.js` (same injection seam for tests), written write-through on every mute/volume change (per AUD-04; per pattern in `js/game.js` `loadBest`/`saveBest`). Verifiable: Node tests with a stubbed storage assert load-defaults, save-on-change, and reload-round-trip. — **Reversibility:** costly once shipped (persisted user data), hence escalated and explicitly approved by the user before planning.
- **D-N11 (user-adopted 2026-10-22 00:45):** Forgiveness expression is **forgiveness-only** in v1: a press inside the buffer window grants pass-forgiveness consumed at the feet-crossing; it does NOT auto-fire the jump when the window opens — the player's own release still times the actual jump (per FEEL-01 criterion wording "forgiven instead of tripping"; user ruling on the escalated taste item). Verifiable: sim tests assert no jump occurs at window-open and a trip is resolved to a forgiven pass at crossing. — **Reversibility:** reversible — flipping to auto-fire is a behavior change localized to the buffer consumption point (D-N01).
- **D-N12 (user-provisional 2026-10-22 00:45):** Juice magnitude seeds are PROVISIONAL data-table values, tuning is morning playtest work: hitstop trip 80 ms / near-miss 40 ms / skip ≤16 ms, shake ≤2 post-pass px, particle counts small and pooled — all living in the D-N06 tier table as the single source of truth so re-tuning is a data-only diff (user ruling on the escalated taste item; tier structure per D-N06). — **Reversibility:** reversible — pure data change in one table.
